# Proposal

## Why

Сборка и проверенная публикация образов уже доступны локально, но обновление Python и выпуск образов требуют ручных действий. Нужен полный автомат в публичном GitHub-репозитории: обнаружение доступного релиза Python в Astral, фиксация входных данных, сборка, проверки и публикация в Docker Hub без PR, ручного merge или подтверждения каждого релиза.

## What Changes

- Добавить GitHub Actions с ежедневной проверкой релизов Astral, проверками PR в `main`, публикацией на push в `main` и ручным запуском на `main` для восстановления.
- По расписанию и при ручном запуске использовать существующий `update_python_manifest.py`: выбирать стабильные Python 3.13/3.14 с GIL и stripped GNU Linux artifacts для amd64/arm64. Новые версии, URL и SHA-256 вместе с согласованным Bazel lock-файлом автоматически коммитить в `main`; без изменений не создавать коммит. Другие зависимости автоматически не обновлять.
- Проверять Python 3.13/3.14 на amd64/arm64, включая запуск Python, Java и JPype/POI; PR выполнять без Docker Hub credentials и публикации.
- После фиксации обновления продолжать публикацию в том же запуске из точного чистого коммита, не ожидая нового push workflow от бота. Использовать существующий `release.sh --channel` для обоих minors: публиковать неизменяемые OCI indexes и после проверок обновлять `3.13-java21-debian13` и `3.14-java21-debian13`.
- Следующий ежедневный запуск автоматически повторяет идемпотентную публикацию текущего коммита, даже если новых входных данных нет: это восстанавливает выпуск после сбоя без дополнительного коммита, перезаписи immutable tags или ручного запуска.
- Использовать стандартные Ubuntu runners в публичном GitHub-репозитории; исключить платные runners, платные сервисы и хранение сборочных артефактов/кешей в Actions в первой версии.
- Настраивать Docker Hub destination и credentials через GitHub Variables/Secrets; сериализовать обновления и публикации. В `CONTRIBUTING.md` описать однократную настройку Actions, разрешение боту писать в `main` и ограничения расписания GitHub.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `dockerhub-image-publication`: добавить hosted CI, автоматическое обнаружение и фиксацию релизов Python, публикацию из доверенной ветки без участия оператора, повтор после сбоев, внешнюю настройку credentials и сериализацию CI-релизов. Существующий контракт выбора Python и требования к тегам, обеим платформам и проверкам сохраняются.

## Impact

Новый `.github/workflows/ci.yml`, обновление `CONTRIBUTING.md` и минимальные проверки автоматического обновления и workflow. Бот меняет только `python_runtimes.MODULE.bazel` и необходимый `MODULE.bazel.lock`; permission `contents: write` требуется только job обновления. Повторно используются updater, `release.sh`, `smoke_test.sh`, `Dockerfile.poi-smoke`, существующие regression checks и Bazel targets; новый runtime Dockerfile или release engine не нужны. Workflow потребует QEMU для ARM64 и Docker с API 1.49+ и containerd image store. Публичность GitHub/Docker Hub репозиториев и возможность записи бота в `main` — условия активации, а не действия по смене видимости или обходу branch protection.
