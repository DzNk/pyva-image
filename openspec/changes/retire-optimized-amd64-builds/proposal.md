# Proposal

## Why

Отдельные сборки `amd64-v2` и `amd64-v3` требуют дополнительных архивов и задач CI. Для новых релизов достаточно четырёх сочетаний Python и Java с базовыми `amd64` и `arm64` в каждом индексе.

## What Changes

- **BREAKING** Убрать цели `amd64-v2/v3` в Bazel, опцию `--cpu` у `release.sh` и `smoke_test.sh` и соответствующие строки в матрице GitHub Actions.
- Обновлять только четыре базовых архива Astral для Python 3.13 и 3.14. Сохранить проверки версий, runtime, POI и digest для обеих архитектур.
- Оставить в Docker Hub ранее опубликованные CPU-теги. Дальнейшие релизы обновляют только четыре канала семейств Python и Java.

## Capabilities

### New Capabilities

### Modified Capabilities

- `python-minor-image-builds` — одна сборка на архитектуру для каждого сочетания Python и Java, без обязательных архивов v2/v3.
- `dockerhub-image-publication` — четыре двухплатформенных индекса в CI и завершение публикации CPU-специфичных тегов.

## Impact

Цели и правила Bazel, генератор и закреплённые inputs Python, сценарии выпуска и проверки, CI, тесты и инструкции для потребителей. Потребители CPU-специфичных каналов могут продолжать использовать опубликованные ссылки или перейти на поддерживаемый канал своего семейства.
